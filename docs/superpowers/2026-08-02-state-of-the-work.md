## 2. 尚未解決的問題

### 2.1 系統缺陷(2 個,都建議先別急著改)

**A. 相關性停滯會讓艦隊永久分裂** —— 這是 **G4 consensus barrier 的既有缺陷,不是這條線造成的**。

一次錯過 20 ms 交換,三隻各自卡在不同 barrier phase 且永不重新同步;每隻對每隻都顯得沉默,
第一個跳到 10 slot 的沉默計數器把其他人全驅逐,對方再以「它的名冊排除我們」反踢回去,分裂自我封閉。

- 實測 `d_0801_075028`(無攻擊者):sim 355.724 三隻同時 timeout,r1 卡 `z`、r2 卡 `xi`、r3 卡 `xi`
- **不是時鐘漂移、不是 mailbox prune 窗**:cycle 計數全程完全同步(11 點抽查)
- **只觀察到一次**,重跑那趟因別的原因先失敗
- ➡️ **該做的是先跑 3 趟重現,不是憑一次觀察去動最危險的程式**

**B. 斷續說謊仍可逃掉** —— lying burst 比定罪深度短就逃（P=2: 0/3、P=10: 1/3）。
`153429e` 落地後可以重新評估,因為信任帳目變了。

### 2.2 等決定的設計選擇(2 個)

`peer_odom_`,兩者都**不是** `peer_truth_`。所以保守錨定覆蓋活體屏障與 `set_peer_keepout`,
**但不覆蓋屍體禁區** —— 而那正是謊言落點（九趟平移 0.392–0.426 m）。

## 4. 論文方向

### 4.1 定位（規格 §12,今天沒有改變它）

HOCBF、Laplacian formation、ADMM-DMPC **三者各自引用來源,不對任何單一元件宣稱 novelty**。
系統段寫「整合 + 真分散部署」。主貢獻三個:

**(a) 失效幾何** —— 偵測門檻與安全緩衝的耦合、安全預算由**謊言位移**而非速度決定、
共識活性死鎖的分類。

**(b) 分層防禦** —— 物理安全（保守錨定）**不依賴偵測延遲**;偵測層只決定協作與成員資格。

**(c) 觀測式信任層** —— 常數由系統自身物理導出,含明確適用範圍與失效模式。

### 4.2 今天讀到的文獻（實際讀了原文,不是摘要）

**Gil 的機制**（2026-08-03 讀完全文,**修正 08-02 的兩個誤判**,細節見
`specs/2026-07-31-related-work-scan.md` §5a）:信賴權重是**兩個**指標的乘積
`α = β × Π(1−γ)`,其中 **`β` = honesty metric,比對「宣稱方向」vs「訊號實際到達方向」——
這就是謊報位置偵測**;`γ` 才是 Sybil。所以 08-02 寫的「它不驗證你在哪」是錯的。

但它有三個限制,每個都是我們的機會:
1. **它也沒解共同座標系 —— 用 Vicon 拿 server 自身位姿。** 跟我們的 Gazebo 是同一根拐杖。
2. **只驗方位角 → 徑向盲軸**:沿視線方向的謊報角度變化恰好 0.00°,偵測不到。
   而「我比實際更遠」正是最吃安全裕度的謊。**我們用位置,沒有這條盲軸。**
3. **Theorem 5.4 假設攻擊者回報隨機位置**;我們的是瞄準式 0.42 m 小謊,不在保證內。

實測 σ̂ ≈ 2°（理論 0.7° + 回報位置誤差）。換算:兩狗距 1.40 m 時 1σ̂ = 0.049 m,
我們的 0.15 m 邊界 = 3.1σ̂ ✅;但距離拉到 4 m 就只剩 1.1σ̂ ❌ —— **角度法距離越遠越差**,
而我們的隊形邊長 1.40 m 正好在可用邊緣。

➡️ **「謊報位置 + 物理安全保證」這個組合,在今天讀到的文獻裡沒有人做。**
與 repo 掃描檔 §3 一致（arXiv:2501.00973 明講現有抗攻擊策略忽略碰撞避免這類約束）。
